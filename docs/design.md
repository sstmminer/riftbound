# 实现结构

`catalog.py` 读取固定卡牌快照并验证哈希；`support.py` 明确列出可执行卡牌。`origins.py` 实现对应卡池的 Rules 协议。未知效果在套牌载入时拒绝，而不是在游戏中当作空效果。

`engine.py` 对动作进行合法性检查，以独立状态和 RNG 副本执行每一步；结算或校验失败时不提交。它提供按玩家裁剪的观测、状态克隆、回放与截断。所有运行态均可 JSON 序列化，Rules 本身没有可变对局状态。

`training.py` 只向策略传递当前玩家观测和合法动作。`policies.py` 的贪心基准与随机基准展示接口，不访问引擎隐藏状态。奖励按玩家索引排列，合法动作明确指定下一决策者，不能假定严格交替。

## 状态机

阶段包括 mulligan、main、move_select、trigger_order、optional、decision、chain、showdown、damage。回合开始/结束的强制步骤运行到下一个决策点。移动选择和伤害分配采用分步动作，避免枚举所有单位组合或所有伤害分配的阶乘增长；选中的移动单位在 commit_move 时同时移动。可选效果会暂停原阶段并保存返回点；多目标决策逐个收集目标，必须显式确认后才继续结算。

Accelerate 是出牌流程内的暂停决策，而不是单位入场后的独立触发。出牌者在支付基础费用后声明是否支付可选的 `[1][C]` 额外费用；支付期间只开放带 Reaction 的 Add-resource 动作，因而可以横置符文获得能量、回收符文获得该符文领域的符能，再确认额外费用。为方便图形界面，单位可以以 `pending` 状态预览在目标位置，但在选择完成前不转移优先权，也不让其他动作插入。支付成功后以 Ready 替代通常的 exhausted 入场；该替代不会触发“变为 Ready”的能力（RUP5 805.2、805.6、805.6.a）。

物理卡牌 ID 和单位对象 ID 分离：同一张实体牌离开棋盘后再次进场会得到新的对象 ID，旧法术目标不会错误命中新对象。符文总数、实体主牌唯一归属、能量非负、对象唯一性和中立状态战场控制在每步校验。

支持卡池的同时触发只涉及同一控制者；处理器显式列出所有触发，多个触发由玩家选择入链顺序。可选触发进入 FIFO 队列，同一控制者同时得到多个选项时先选择顺序，再逐项确认触发或跳过。触发链关闭不转移 Focus；玩家发起的法术链关闭时转移 Focus。基础符文和传奇 Add 能力立即结算。

## 扩展卡牌

1. 更新固定数据及勘误来源；保留原始/生效文本与未知状态。
2. 为新卡写显式处理器及正反例，检查它引入的全局规则交互。
3. 将卡牌加入支持表；若它要求新时机、替代效果或关键词，先实现该机制。
4. 执行整套测试、批量自博弈、守恒/信息隔离校验和回放校验；升级语义版本。
5. 再增加真实验收套牌；不要用移除合法性检查的方式扩大卡池。

未来工作包括更多 Origins 卡牌、反制/装备/Hidden、独立裁判场景对照、固定维度编码、PettingZoo/Gymnasium 适配与并行采样。不要把双人奖励向量直接冒充 Gymnasium 单人标量奖励。
